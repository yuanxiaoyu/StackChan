# StackChan GAME 使用与验证

开发分支：`codex/fc-emulator-feasibility`。基于官方 ESP-IDF 6.1 / Mooncake / HAL，新增 GAME 和 Setup → Apps → Gamepad / 蓝牙手柄。

## 内存卡和游戏

当前手柄测试版本内置《赤色要塞》（Jackal，131,088 字节，Mapper 2）。进入 GAME 会自动加载它，无需 SD 卡。暂停菜单的 Games 可以返回内置游戏列表，再次选择可重新开始。内置 ROM 的构建启用时，游戏列表只显示此游戏，Refresh 不访问 SD 卡；原有 SD 读取问题暂缓到更换 16GB 卡后排查。

构建时通过 `-DSTACKCHAN_BUILTIN_ROM=/绝对路径/jackal.nes` 指定本机 ROM；CMake 将副本放入构建目录并嵌入只读 Flash，启动游戏时复制到 PSRAM。ROM 不提交到 Git。将此 CMake 变量清空后恢复 SD 游戏列表模式；不要将该模式视为 SD 故障已修复。

插入 FAT 格式 microSD，在 `/room` 放未压缩 `.nes` 文件；也兼容 `/rom`、`/roms/nes`、`/roms`、`/ROM` 的直接子文件。支持 UTF-8 长文件名，最多列出 128 个通过检查的文件；点击 Refresh 可重读列表。目录不递归，ZIP、FDS、NES 2.0 不支持。文件上限 1 MiB；当前允许 Mapper 0、1、2、3、4、7、9、10、11、66、71，以实际游戏运行结果为准。

只读原 ROM，不格式化卡、不创建存档。换卡前先退出 GAME；首版暂不支持 SRAM 电池存档或即时存档。256×240 游戏画面横向拉伸到 320×240 全屏，保留像素边缘、不显示侧边栏；横向 4:5 最近邻拉伸与调色板转换在模拟任务内合并处理。点击画面可打开暂停菜单，再选 Start 开始游戏。当前按用户最新要求启用游戏声音，将 APU 生成的 PCM16 输出至现有 24 kHz 音频驱动；用户稍后在适合时自行测试。

## 先用原配遥控器

StickC-Plus + Hat Mini JoyC 没有触摸屏，使用实体按键与摇杆。需要刷入本分支 `remote/code` 构建的游戏版固件；保留原有 Setup、摇杆舵机与 IMU 模式。主机进入 GAME 后自动启用 ESP-NOW，频道固定 1、接收 ID 为 1；遥控器设频道 1、ID 1（也接受默认广播 ID 0）。

1. GAME 模式横握，摇杆在左手边。遥控器用 A 切换到 Setup，松开摇杆，长按 B 一秒进入 GAME；中立位置在进入时校准。GAME 的轴向按此握法旋转 90°，Setup 和舵机模式保留原轴向。
2. 主机游戏列表：摇杆上下选择，A 或中心短按进入；B 退出。空列表时 A 或中心短按重新扫描。
3. 游戏内：摇杆方向，实体 A/B 对应 FC A/B；A 短按射击，单独按住 A 约 0.7 秒打开主机菜单。按下左侧摇杆中心立即按下游戏 Start，松开即释放；标题和选人画面用于开始，关卡内按游戏自身的 Start 逻辑暂停／继续。也可点击主机画面打开菜单。A+B 退出组合不触发长按 A 菜单。
4. 暂停菜单：摇杆上下换行、左右换列，边缘保持原位，A 确认，B 返回游戏列表。第一行 Resume / Games，第二行 Start / Select，底部 Exit Game；从底部向上回到 Start。选择 Start/Select 会发出短按并继续游戏。
5. A+B 同时按住两秒退出遥控器 GAME 模式，主机随后因心跳消失暂停。

若主机菜单能操作但游戏内无响应，先确认遥控器屏幕仍显示 GAME / A/B fire，并在主机选择 Resume。遥控器停在 Setup 时，摇杆调整频道/ID，不发送游戏按键；重新连接串口或重启遥控器后可能回到 Setup，需要重新长按 B 进入 GAME。频道须为 1，ID 为 0 或 1。

原遥控器固件的舵机报文仅提供方向与短 A 脉冲兼容，不能提供完整 FC 操作；请使用新版。新版以 20 ms 心跳发送完整按键，主机在 300 ms 无报文时释放全部按键并暂停。

ESP-NOW 占用现有 Wi-Fi 模式；离开 GAME 会重启回主菜单以恢复日常网络功能，保留已有配置。当前进入 GAME 总会启用此模式，即使已连接蓝牙手柄。

## CodexPad C10 到货后

在 Setup → Apps → Gamepad / 蓝牙手柄点击 Scan，选择手柄名称，等待 Connected；Forget 可忘记连接并重新选择。也支持部分标准 BLE HID 手柄。ESP32-S3 不支持 Bluetooth Classic。

C10 按官方 Python 库的 FFA0 服务 / FFA1 通知、8 字节状态协议适配，并非假定它使用标准 HID。蓝牙连接成功时优先采用蓝牙输入；方向键/左摇杆、A/B、Start/Select 用于游戏，Menu 或 Start+Select 长按 0.5 秒打开暂停菜单。设备身份和 BLE bond 保存在 NVS，自动重连。C10 尚在邮寄，未进行实机按键/重连验收。

蓝牙服务复用官方现有单一 NimBLE host，未添加第二个蓝牙协议栈；扫描列表可包含尚未确认支持的 BLE 设备，连接后检查服务/协议并反馈失败原因。

## 内核、图标与构建

内核移植自 [Retro-Go Nofrendo](https://github.com/ducalex/retro-go)，固定提交 `4ced120669750ca7228fd0414211430c1d923166`，源码和上游许可证保存在 `firmware/components/nofrendo`；仓库不包含游戏 ROM，本机测试镜像可通过上述选项内置游戏。C10 协议参考 [官方 codex_pad_bleak_lib](https://github.com/CodexPad/codex_pad_bleak_lib/blob/main/codex_pad.py)。

GAME 图标使用现有 188×150 RGB565A8 资产格式，透明背景、粗黑轮廓和 FC 红灰配色；可用 `python3 scripts/generate-game-icon.py` 重建，预览在 `docs/design/game-icon.png`。

主机使用 ESP-IDF 6.1，遥控器使用 ESP-IDF 5.5.4（原仓库标注 5.4.2，验证环境未安装该版本），依赖及 M5GFX legacy-I2C 补丁见 `remote/code/README.md`。烧录前备份，避免使用会覆盖主机 NVS、OTA 数据或分区表的全量 flash 命令。遥控器升级也需先核对设备型号与分区。

## 验证记录（2026-11-13）

- 宿主 CTest：8/8 通过，覆盖既有运动/看板/手势、遥控协议、ROM 边界、HID/C10 解码、模拟核心及 trainer/音频分配失败。
- 独立审查发现并修复 trainer 未装入 PRG RAM、APU 分配失败与蓝牙断连覆盖错误提示问题。
- 遥控器 ESP32 固件编译通过。已识别 M5StickC PLUS（ESP32-PICO-D4、4MB Flash），完整备份原 Flash 后仅更新 `0x10000` 应用分区，写入校验通过；保留原引导程序、分区表和 NVS。启动日志已确认 M5StickCPlus、135×240 屏幕、Mini JoyC I2C 地址 0x54 和 ESP-NOW 2.5.3 初始化成功。游戏按键变化及进入模式的校准结果输出到 `GAME-REMOTE` 日志，端到端按键和断连验收仍待完成。
- 首次 GAME 试用记录到 Mini JoyC 读取失败、B 按下/释放有发送日志。对照官方 HAT 固件确认原先从 0x00 读四字节的游戏读取方式有误，已改为 0x00、0x02 各读两字节并重新烧录、校验通过。修正版随后启动时未扫描到 0x54，需先将 HAT 断电重插，再验证方向和中心键；不能将该代码修正视为摇杆实机验收通过。
- 主机静音版已仅写入应用分区并通过校验，用户确认游戏无声音且持续运行；实测模拟逻辑约 60 FPS。遥控器发往主机的 7 字节报文已实机收到（频道 1，RSSI 约 -25 至 -40），但摇杆失败时三次 200 ms 等待使收包间隔约 600 ms，超过 300 ms 断连阈值。已改为游戏读取每次最多等待 10 ms、首次失败即返回，并限制等待摇杆互斥锁的时间；该修正需要重新实测收包间隔和按键。
- 后续实测：限制读取等待后，主机可持续收到遥控器心跳，但拨动摇杆时仍没有方向位。对照 HAT 的 STM32 `ListenCplt` 回调，将所有模式的寄存器读取统一为写寄存器 + STOP，再单独读取，遥控器构建及应用分区烧录校验通过。现场仍在寄存器 0x00 超时，SDA=1、SCL=0；用户重新连接后暂停菜单仍不移动，启动扫描未找到 0x54；随后用户说明 HAT 用螺丝固定、没有工具，尚未实际取下模块，因此不能把之前的重插反馈当成 HAT 已彻底断电。初始化前释放引脚的诊断仍记录 SDA=1、SCL=0。改为拔 USB 并长按整机电源键关机，验证完全断电重启。协议修正尚未通过摇杆实机验证，不能视为已修复。
- 整机完全断电后，初始化前后均恢复 SDA=1、SCL=1，并扫描到 0x54；进入 GAME 时在寄存器 0x02 超时，随后再次出现 SCL=0。正在以写入和读取后各留 20 ms 的保守节奏诊断 HAT 回调时序，暂未验收；此诊断版本会降低采样和心跳频率，不能按稳定版 20 ms 心跳描述。中途曾发生应用写入不完整，启动日志为 `invalid segment length 0xffffffff`；仅比较镜像头不能证明完整烧录，需以全镜像写入校验及正常启动日志确认恢复。
- 20 ms 间隔版已重新完整烧录并通过哈希校验，确认应用正常启动；完全断电后，Setup 连续读到 X≈2052、Y≈2197。进入 GAME 后日志出现 Up=0x010、Down=0x020、Left=0x040、Right=0x080，用户确认暂停菜单能移动且方向正常。仍有间歇读取超时（SDA/SCL 均为 1），当前完整采样约 120 ms；A/B 与中心键、输入稳定性尚待继续验证，不能宣称手柄已全面验收。
- 用户随后纠正方向反馈：上推时菜单从 Resume 移向 Games。检查确认暂停菜单把上下左右统一为线性前后项，与屏幕两列布局不符；已改成按行列导航并限制边缘，新增回归测试先复现原错误，再验证修正，宿主测试 9/9 通过。物理上推的单独核对期间 USB 连接中断，未取得该次报文，因此未擅自反转摇杆轴向；不能沿用上一条“方向正常”作为验收结论。A/B、中心键及输入采样速度仍待验证。
- 菜单布局修正版主机镜像 4,642,768 字节，应用分区剩余 534,576 字节；先备份当前完整应用分区，再仅写入 0x20000 应用并通过哈希校验。启动后收到正常 SystemInfo 心跳，未观察到异常重启；全屏、临时静音及既有显示调度代码保留。新布局的实机方向与确认按键尚未验收。
- 用户进一步说明手柄横握、摇杆在左，原 GAME 映射仍按竖握，是上下与左右互换的原因。已将 GAME 的原 X 正/负映射为上/下，原 Y 正/负映射为左/右，保留斜向与死区；不改变 Setup/舵机轴向。横握映射回归测试先在旧映射上失败，再在旋转映射上通过，全部宿主测试 9/9 通过。遥控器重新构建通过，镜像 1,157,040 字节；实机横握方向仍需烧录后验证。
- 横握版遥控器已仅烧录 0x10000 应用并通过完整哈希校验，启动日志确认新 ELF `a2605b4af…`，扫描到 0x54 并读到正常 X/Y。用户按摇杆在左横握，从暂停菜单 Resume 依次拨下、右、上、左，确认高亮完全符合 Start、Select、Games、Resume，横握四方向和菜单行列导航已实机验收。测试过程中 USB 连接曾断开，未获得该轮完整串口方向记录；该验收依据用户屏幕反馈。仍保留保守的约 120 ms 采样，A/B、中心键和间歇读取超时未宣称已解决。
